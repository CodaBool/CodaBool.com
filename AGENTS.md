# codabool.com

Personal portfolio and blog. A client-only React SPA built with Vite and served as static assets on Cloudflare Workers. There is no worker script and no SSR: `wrangler.toml` falls back to `index.html` for every unknown path, and routing happens in `src/App.jsx`.

## Verify

The project has no tests or linter, so `npm run build` is the check. It must pass before you call a change done. Use `npm run dev` to look at a page.

## Deploy

`npm run deploy` builds and runs `wrangler deploy`. The site is no longer on Vercel. `codabool.com` and `www.codabool.com` are attached as Worker custom domains through `routes` in `wrangler.toml`, so keep those entries; they're the record of how the domain is wired. Because routes are set, the `workers.dev` and preview URLs are disabled.

## Blog posts

- A post is `content/posts/<id>.mdx`. The numeric `id` in its metadata must match the filename, because the slug `/blog/<id>` comes from both.
- `plugins/posts.js` reads metadata with a regex and evaluates it **without compiling the MDX**. The block has to be a self-contained object literal that starts at `export const metadata = {` and closes with `}` at column 0. Don't put imports, variables, or expressions in it. Fields: `title`, `description`, `publishedTime` (`YYYY-MM-DD`), `cover`, `tags` (a comma-separated string), `id`.
- Post bodies use `Img`, `Video`, `a`, and `p` without importing them. These are registered in `src/components/mdx-components.jsx`, and any new component a post uses gets added there.
- Post images go in `public/posts/<id>/` and covers go in `public/coverImg/`.
- `/rss.xml` is generated by the same plugin, served by middleware in dev and emitted at build. It is not a file in `public/`.
- At build, the same plugin also writes `dist/blog/<id>.html`, a copy of `index.html` with the post's title, description, OpenGraph, and Twitter tags, so crawlers and link previews get per-post metadata. Workers assets serves it at `/blog/<id>`. Every other route gets the plain `index.html`. Metadata that a page needs to show in link previews has to come from here, not from `useTitle`.

## App structure

- `MainLayout` wraps nav and footer around the site pages. `ExternalLayout` (`/maps`, `/module`) is for pages linked from itch.io and has no chrome.
- Every page calls `useTitle(title, description)` from `src/lib/useTitle.js`. That hook is the only place title and meta description get set at runtime. Leave out `description` and it falls back to the site default, which has to stay in sync with `index.html`.
- Import with the `@/` alias, which maps to `src/`. Router imports come from `react-router` (v8), not `react-router-dom`.
- Tailwind v4 is configured in CSS (`src/styles/globals.css` `@theme`), and there is no `tailwind.config`. `src/components/ui/` holds hand-maintained shadcn-style components.
- `landing/` is the legacy Create React App source for the `/` terminal intro. It has already been ported to `src/pages/Landing.jsx` and `src/components/landing/`, it isn't part of the build, and it is kept only as reference.

## Style

Use 2-space indent, single quotes in JS, no semicolons, and plain `.jsx` files (no TypeScript). Keep comments short and lowercase, matching the existing ones.
